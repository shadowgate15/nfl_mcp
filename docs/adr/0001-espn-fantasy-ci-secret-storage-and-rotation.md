# CI secret storage and rotation for the ESPN fantasy contracts check

The daily `.github/workflows/contracts.yml` ("Source Contracts") check gains its first check backed by stored secrets: an ESPN Fantasy check authenticating to the maintainer's own real private league via `espn_s2`/`SWID` cookies, stored as plain GitHub Actions repo secrets `ESPN_S2`/`ESPN_SWID` (no Environment scoping — every other check in `evals/contracts/checks.py` is public/keyless, and this repo has one workflow needing them). The new `@check(..., critical=True)` entry is critical like the rest of the file, so a stale-cookie failure reddens the daily build and rides GitHub's existing failed-workflow notification rather than a separate warning-annotation mechanism. Because a critical failure here can mean either "ESPN changed their API shape" or "the cookies expired" — two very different responses — the check catches `httpx.HTTPStatusError` and special-cases `401`/`403` into a distinct message ("ESPN cookies expired — rerun the cookie-pull script"), reusing the same expired-cookie detection the `espn_fantasy_tools.py` module uses at the tool level rather than a second detector. Rotation is reactive only: no proactive/calendar-based refresh, since ESPN's cookie lifetime isn't fixed — the daily check's failure is itself the trigger to rerun the local cookie-pull script and update the two secrets. The private league ID is a hardcoded literal in `checks.py` next to the check function (not a secret, not a repo variable), matching how every existing check hardcodes its own target.

## Considered Options

- **Dedicated throwaway ESPN account/league for CI**, decoupled from the maintainer's real league. Rejected: adds a second account and an artificial league to maintain shape parity with a real one, for no real isolation benefit in a solo-maintainer repo.
- **Non-critical (warn) severity**, so routine cookie expiry doesn't redden the build. Rejected: a warn-level failure doesn't fail the job, so nothing would prompt the maintainer to notice it without actively reading logs; critical severity plus the distinct expired-cookie message gives a reliable notification while still being distinguishable from a genuine break.
- **Proactive/calendar-based cookie rotation.** Rejected: ESPN's cookie lifetime isn't well-documented or fixed, so a guessed cadence would rotate too early (wasted effort) or too late (a gap where the check is already failing) — the daily check is already the expiry detector.
